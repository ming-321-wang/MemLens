# MemLens 使用指南

> 面向「电子数据取证 / CTF 攻防检材分析」的一体化分析工具。
> 覆盖：**内存镜像（Win/Linux/macOS）· 磁盘/加密卷 · 抓包 · APK · 服务器磁盘（XFS）**。
> 本文按「能不能立刻上手 → 逐功能 → 典型工作流 → 注意事项」组织，建议从第 1、2 节读起。

---

## 0. 一句话定位

MemLens 把「打开检材 → 全量深度分析 → 按取证对象分类浏览 → 跨产物检索 → 出报告/旗标」
这条链路做成了一个本地桌面/ Web 工具：

- **内存镜像**（`.dmp` / `.raw` / `.lime` / `.vmem`）：进程 / 网络 / 注册表 / 凭据 / 时间线。
- **取证容器**（`VeraCrypt 加密卷 / EWF(E01) / VMDK / pcapng / APK`）：不解包落盘即可识别、列文件、提取、分析。
- **服务器磁盘（XFS）**：`加密卷 → exFAT → VMDK → LVM → XFS` 全链路只读挂载，读超级块 / 定位 inode / 读文件。
- **跨产物检索**：对已产出的所有分析结果做一次查询（支持 `key:value`、短语、正则、排除）。

所有分析**只读**，检材文件不会被改动（出证友好）。

## 1. 快速上手（3 种启动方式）

| 方式 | 命令 | 场景 |
|---|---|---|

## 3. 取证容器通道（加密卷 / EWF / VMDK / 抓包 / APK / **XFS**）

界面里叫「🧰 取证容器（非内存镜像检材）」卡片。字段：

| 字段 | 说明 |
|---|---|
| `ctPath` | 目标文件**绝对路径**，例如 `E:\cases\平航杯题目` |
| `ctPw` | 加密卷口令（可选；VeraCrypt 卷必填） |
| `ctKind` | 动作：识别类型 / 列出卷内文件 / 卷头详情 / 提取卷内文件 / 抓包分析 / APK 属性 / **磁盘·XFS** |
| `ctInner` | 卷内路径（「提取」时填） |

动作清单（`ctKind`）：
- **类型识别**：按魔数判定 VeraCrypt / EWF / VMDK / zip / pcapng / APK / BLE / HID。
- **列出卷内文件**：进 exFAT / zip / APK 列出文件。
- **卷头详情**：VeraCrypt 卷的加密算法 / 密钥长度等（不落地）。
- **提取卷内文件**：按 `ctInner` 路径提取单个文件到「产物」。
- **抓包分析**：pcapng 的接口 / 蓝牙设备表 / 蓝牙改名事件 / USB 键盘还原。
- **APK 属性**：包名 / 应用名 / 权限 / 加固 / IOC / flag 串。
- **磁盘·XFS（新）**：见下一节。

> 关键点：**容器内检索**（`srCtPath` / `srCtRun`）可以直接在加密卷里按内容检索
> （VeraCrypt 卷 → exFAT → 逐文件扫），**不需要先解包落盘**。CTF 找 flag / 字符串非常实用。

### 3.1 平航杯式「加密卷里套虚拟机盘」全链路

检材是 VeraCrypt 容器，里面是一个 exFAT，exFAT 里是一个 VMDK（客户机磁盘），
根文件系统还在 **LVM 逻辑卷**里（XFS）。MemLens 现在能一路只读读穿：

```
VeraCrypt 卷  ─(口令)─▶  exFAT  ─▶  export-disk0-000002.vmdk
VMDK（monolithicSparse，grain=128 扇区）
   └─ MBR 分区：part1 = XFS /boot（1 GiB），part2 = LVM PV（0x8E，49 GiB）
        └─ LVM VG：LV swap（PE0–991）、LV root（PE992–12541，45.12 GiB，XFS）
             └─ XFS（v3，4 KiB 块，rootino=64）
```

## 4. XFS 阅读器（服务器磁盘取证，本次新增）

新增两个「磁盘」分组插件：

| 插件 | 作用 | 参数 |
|---|---|---|
| `container.xfs` | 挂 VMDK→LVM→XFS：磁盘布局、超级块、inode 表、清单、单文件详情 | `password` `lv=root` `scan=GiB数` `ino=单查` `list=top` `limit=N` |
| `container.xfs_read` | 按 inode 号读 XFS 文件（save/text/hex 三模式） | `ino` `mode=save/text/hex` `limit=字节` `password` `lv` |

**功能说明**：
- `xfs` 默认输出：**磁盘布局**（VMDK → 分区表 → LVM → 超级块）+ inode 扫描进度 + 抽样。
- `xfs` + `ino=72`：只看 inode 72 详情 + 数据预览（不扫描，秒级）。
- `xfs` + `list=top` + `limit=5`：扫 inode 表并按大小列 top 5 文件。
- `xfs_read` + `mode=text`：文本预览（≤8KB）；`mode=hex`：hex 预览（≤512B）；`mode=save`（默认）：写文件到 `work/extract/`。

### 4.1 Web UI 用法（推荐）
「🧰 取证容器」卡片里：
1. `ctPath` = VeraCrypt 卷绝对路径（如 `E:\2025平航杯\平航杯题目`）。
2. `ctPw` = 口令（VeraCrypt 卷必填）。
3. `ctKind` 下拉选 **「磁盘·XFS 分析」**（`xfs`）或 **「XFS 读文件（按 inode）」**（`xfs_read`）。
4. `xfs`：填 `LVM 逻辑卷名`（默认 `root`）、`扫描GiB`（默认 1）；可选 `inode号`（单查详情）、
   `list: top`（列最大文件）、`limit`（条数）。
5. `xfs_read`：填 `inode号`（如 `72`）和 `mode`（`save`/`text`/`hex`，默认 save）。
6. 点「执行」，进度和结果出现在下方（磁盘布局 / 超级块 / inode 清单 / 文件内容）。

> ⚠ 若下拉里还没出现「磁盘·XFS 分析」，说明 Web 服务跑的是**旧代码**：
> 重启 MemLens 服务（关掉当前窗口的 MemLens.exe，重新 `MemLens.exe`）即可加载新插件。
> 源码运行则重启 `python main.py`。


### 4.3 直接用 `Xfs` 类（写脚本 / 复现）
```python
from memlens.formats.xfs import Xfs, open_server_fs

# 一条命令开到服务器根 XFS
x, meta = open_server_fs(r"E:\2025平航杯\平航杯题目",
                         password="早起王的爱恋日记❤", lv_name="root")
print(x.summary())          # 超级块
x.find_inodes(4 << 30)      # 定位前 4 GiB 的 inode（大卷可分段累加）
data = x.read_inode_data(72)  # 按 inode 读文件内容
```

### 4.4 关键实现点（为什么这么写）

本检材的 XFS 是**出题方脚本合成的**，部分元数据不可信，阅读器因此采用
「内容优先 + 魔数锚定 + 逐层校验」：

| 层 | 可信字段 | 不可信字段（合成 FS 实测） |
|---|---|---|
| 超级块 | magic/blocksize/dblocks/rootino/ag* | — |
| LVM 元数据 | `pe_start`、`extent_size`、`stripes` 起点 | **`start_extent`（全 0）** |
| dinode(v3) | mode/size/di_ino | bmbt 的 **blockcount**（用 di_size 定长） |
| bmbt extent | `startoff`、`startblock`（标准 128-bit 解法） | blockcount |
| dir3 数据块 | owner、名字 | 条目里的 **inumber**（常为 0/假值） |
| inobt 树 | — | **子指针全 0 + 假 blkno（整棵树不可用）** |

因此：
- **文件内容**靠 `di_size` + `startblock` 读，不依赖 btree / inobt。
- **inode 定位**靠全卷扫 `"IN"`（0x494E @512B 边界），不依赖 inobt。
- **目录名**靠 dir3 块的 owner + 名字串，不依赖条目 ino 字段。

> 已知限制：根目录（ino 64）的 dir3 块与 inode 的 bmbt **不互相关联**，
> 所以完整目录树走不通；能可靠拿到的是「超级块 + inode 表 + 任意文件内容 + 目录名」。
> 要按路径取文件时，先用**内容扫描**定位，再按 inode 读全文（见第 6 节工作流）。

## 6. 典型工作流

### 6.1 CTF / 平航杯「服务器取证」16 题
1. 容器通道：`ctPath`=VeraCrypt 卷，`ctPw`=口令，`ctKind`=磁盘·XFS，`lv=root`。
2. 读超级块确认 XFS；`scan` 给足（4 GiB 起，大卷加到 16/45 GiB）。
3. 定位关键文件：
   - `container.xfs_read` 按 inode 读（先用内容扫描拿到 inode 号）；
   - 或「容器内检索」直接搜字符串（如 `wyzshop1.com`、`3.10.0-1160`）。
4. 对照题目逐条落证。本检材已核实的关键点：
   - 内核 `3.10.0-1160.119.1.el7.x86_64`（`/usr/src/kernels/…`）；
   - 攻击者 shell 历史：`trojan-1.16.0… > /usr/local/bin/trojan`、`mysql -uroot -p`、
     `chmod 777 ./teamserver`、`yum install java-11`；
   - `/root/AndroRAT/Android_Code/`（gradle 工程）；
   - trojan `config.json`（`remote_addr=wyzshop1.com`、`remote_port=443`、
     `local_port=12345`、`password=["password1"]`，`run_type` 被改成 `"you guess"` → 实为 **nat** 模式）；
   - 宝塔面板（`/www/server/panel/BTPanel`）、neo4j、mysql。

### 6.2 内存镜像（`.dmp/.raw/.lime`）
打开后自动跑：进程 / 句柄 / 网络 / 注册表 / 凭据 / 时间线。
用「分析分组」左侧导航直达；「时间线」看事件顺序；「发现项/情报」看 IOC。

### 6.3 抓包（BLE / USB-HID）
`ctKind`=抓包分析 → 选「接口信息 / 蓝牙设备表 / 蓝牙改名事件 / USB 键盘还原」。

### 6.4 出报告
「合规 / 出证」页有链式哈希与取证合规信息；「产物」页下载提取件；
需要正式 docx 报告时，可用配套的 `lab-report-docx` 技能把分析结果排版成实验/取证报告。

## 8. 注意事项 / 排障

1. **端口被占**：`--port` 换端口；exe 无控制台，排障看 `MemLens.log`。
2. **依赖缺失**：源码运行需 `uvicorn[standard] fastapi`；用官方 exe 则自带。
3. **大镜像首析慢**：正常。内存镜像按插件逐个跑；磁盘 XFS 按 LVM 链路 + inode 扫描（`scan` 越大越慢，4 GiB 约 1–3 分钟）。
4. **合成 FS 元数据不可信**：inobt / dir3 ino / bmbt blockcount / LVM start_extent 都可能是假值，
   一律以「超级块 + 魔数锚定 + di_size + 内容扫描」为准（第 4.3 节）。
5. **只读**：MemLens 不写检材；提取件落在 `work/` 与「产物」，可自由保存。
6. **exFAT 大文件 / 稀疏 VMDK**：阅读器已做 grain 级批量读 + 4 MiB 对齐缓存，避免逐扇区解密拖速。
